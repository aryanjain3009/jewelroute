# Backend decisions (apps/api)

- **Nest 11 + Express, compiled with plain `tsc`** (decorator metadata preserved). `src/main.ts` listens locally; `api/index.ts` is the Vercel function and just `require`s `dist/serverless`, which boots Nest once per instance and reuses the Express handler.
- **Prisma 6.19 with `output = "../generated/prisma"`** so the query engine (`native` + `rhel-openssl-3.0.x`) lives inside `apps/api` and is bundled by `vercel.json` `includeFiles` — avoids the pnpm-symlink "engine not found" failure on Vercel.
- **zod** for every DTO (one `parse()` helper → `400 VALIDATION_FAILED`). Swagger documents routes/tags/headers; body schemas are in CONTRACT.md.
- **Tenant scoping**: `tenantId` only from the verified JWT (`ReqCtx.user.tid`); every query filters by it; other-tenant and other-agent ids return 404 (no existence leak). Tested.
- **RBAC as permissions** (`field`, `admin`, `admin.read`) mapped from roles in `ROLE_PERMISSIONS`; a new role is one map entry.
- **Invariants in SQL** (`prisma/migrations/20261021000000_init/migration.sql`, tail): partial unique index "one CHECKED_IN/ACTIVE visit per agent", partial unique "one OUT MemoItem per piece", CHECK "custodian column matches custodianType", value/weight CHECKs, append-only triggers on GoldRate / CustodyEvent / OrderItem. The only escape hatch is a transaction-local `jewelroute.allow_purge` flag used by the seed to wipe a tenant (DELETE only, never UPDATE).
- **Check-in**: `SELECT … FOR UPDATE` on the visit + status/today/other-open checks + the partial index as the final race guard (unique violation → `ANOTHER_VISIT_OPEN`). Distance recomputed server-side with shared `distanceM`/`geofenceDecision`; accuracy slack capped at 50 m. Check-in must be on the planned IST date (`VISIT_NOT_TODAY`).
- **Simulated GPS** only when `tenant.demoMode`; stored as `SIMULATED`, shown in feed titles and dashboards — never upgraded to VERIFIED.
- **Custody**: one helper (`CustodyService.move`) locks pieces `FOR UPDATE ORDER BY id`, verifies the current custodian, bumps `custodySeq`, appends a gap-free `CustodyEvent`, writes one `sample.custody_changed` outbox event per move (with all pieces) and an audit row — always inside the caller's transaction.
- **Idempotency**: the `(tenantId,key)` row is inserted first *inside* the business transaction (`ON CONFLICT DO NOTHING`); concurrent duplicates block on the unique slot and then replay the stored response; different body → 422. Errors roll the key back, so retries after a failure re-execute. `clientOpId` (= key) is unique on Order/Memo as a second line of defence. Replays are deep-equal (jsonb may reorder keys).
- **Pricing** is authoritative on the server using the shared `priceDesign`/`orderTotals`; current rate = latest `effectiveFrom <= now()` row (append-only). OrderItem freezes rate id/rate/components; `goldRateSnapshot` per purity. Memo item value = valuation at handover (exposure).
- **Webhooks without Redis/BullMQ**: Vercel can't host a long-lived worker; the Postgres outbox + `FOR UPDATE SKIP LOCKED` claim with a 30 s lease gives at-least-once delivery with safe concurrency at this scale. Triggers: post-commit `waitUntil(dispatcher.runOnce())`, opportunistic on dashboard/deliveries reads (≤1/10 s/instance), `/v1/internal/dispatch` (cron, daily on Hobby). `DispatchQueue` interface is the BullMQ extension point.
- **Backoff**: 1 immediate attempt + 6 retries (30s/2m/10m/30m/2h/6h), then DEAD; manual retry = one more immediate attempt. Each attempt stores the exact request headers sent (signature, never the secret) and the response truncated to 2 kB. Endpoint secrets AES-256-GCM at rest; reveal/rotate audited.
- **memo.overdue** emitted once per memo (`overdueNotifiedAt`, reset when extended), scanned lazily (≤1/min/instance) and on every cron dispatch.
- **Uploads**: Vercel Blob client tokens scoped to one pathname/type/8 MB when `BLOB_READ_WRITE_TOKEN` is set; otherwise direct upload (≤4 MB) into `StoredFile.bytes` with server-side sha256, served at `/api/v1/files/:id` (auth + tenant scoped). Blob-mode proofs are trusted by URL⇄pathname match (no server re-hash — known gap). EXIF is never read.
- **Retailer ack**: QR → public page shows exact pieces and a 6-digit code `HMAC(APP_SECRET, memoId:token) mod 10^6`; only the token hash and an HMAC of the code are stored; 72 h TTL; 5 wrong codes → 423.
- **Auth**: bcryptjs, 15 min access JWT (sub,tid,role,tslug,name), 30 d rotating refresh tokens stored hashed; reuse of a rotated token revokes the user's whole token family. Cookies httpOnly, `sameSite=lax`, `secure` in production, no Domain.
- **Rate limits** (in-memory per instance — fine for MVP; Redis store is the upgrade): 600/min default, login 10/min, public ack GET 30/min, POST 10/min, ack verify 20/min.
- **Activity feed** = the outbox itself (`title` derived from type + payload), so the feed and webhooks can never disagree.
- **Doc numbers** `ORD-YYYY-NNNNN` / `MEMO-YYYY-NNNNN` / tag codes via a row-locked `DocSequence` upsert (gap-free per tenant).
- **Dates**: business dates are IST (`istDate`), stored as `@db.Date` at UTC midnight.
- **Helmet CSP disabled** (JSON API; Swagger UI assets come from jsDelivr so `/docs` works in the serverless bundle).
- **Migrations + seed on Vercel** (no 5432 egress from the dev workspace): `build` runs `scripts/migrate-on-vercel.cjs` → `prisma migrate deploy` only when `VERCEL=1` (uses `directUrl`; falls back to DATABASE_URL). The seed is `src/seed/seed.ts` → `runSeed()`, compiled into dist (design images imported as JSON), used by both `prisma/seed.ts` and `POST /v1/internal/seed` (CRON_SECRET). Batched with createMany/createManyAndReturn (~1 s locally). Function maxDuration 60 s.
- **v2 record endpoints** live in one `RecordsController` (`src/modules/records.ts`) that also serves the v1 list routes as strict supersets. Builders (`adminVisitRows`, `pieceRows`, `shopRows`, `custodyRows`, `auditRows`, `attention`) take a batch and resolve relations with a constant number of `groupBy` / `DISTINCT ON` / `IN (…)` queries — never per row.
- **Custody ↔ webhook identity**: `CustodyService.move` pre-allocates the `evt_…` id, stamps it on every `CustodyEvent.outboxEventId`, then emits the outbox row with that id — so a piece's ledger row, the webhook payload `id` and the ActivityItem `id` are the same string.
- **Visit attribution of returns/sales**: memo return/convert happen "in" the caller's open visit at the memo's shop (or an explicit open visit there); otherwise no visit. The memo's original visit is never reused.
- **Idempotency-Key is mandatory** for orders, memos, memo return and convert (`400 IDEMPOTENCY_KEY_REQUIRED`). Check-in and proofs dedupe naturally (one open visit; checksum per visit) and still accept keyless calls.
- **MISSED is persisted** by the dispatcher sweep (PLANNED before today IST → MISSED). No webhook event (not in the event list).
- **Unknown GPS accuracy** is not a perfect fix: no slack and never `VERIFIED` (`LOW_ACCURACY`).
- **`GET /visits/:id` `resume`** is the single server-derived answer to "where am I in this visit" for refreshes and app restarts; there are no server-side drafts (orders and memos are written atomically on submit).
